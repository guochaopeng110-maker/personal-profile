# Domain Docs

本文件定义工程技能在探索代码库时如何读取本仓库的领域文档。

## 开始探索前先读这些

- 仓库根目录的 `CONTEXT.md`
- 如果根目录存在 `CONTEXT-MAP.md`，优先读取它；它会指向一个或多个上下文对应的 `CONTEXT.md`
- `docs/adr/` 中与当前工作相关的 ADR

如果这些文件暂时不存在，请静默跳过，不要因为缺失而中断或主动要求创建。等真正需要沉淀术语或架构决策时，再由相应技能补齐。

## 当前布局

本仓库采用 single-context 结构：

```text
/
|- CONTEXT.md
|- docs/adr/
|  |- 0001-some-decision.md
|  `- 0002-another-decision.md
`- src/
```

如果未来演变为多上下文仓库，再切换到 `CONTEXT-MAP.md` + 多个上下文目录的结构。

## 使用 glossary 中的术语

当技能输出领域概念时，比如 issue 标题、重构建议、诊断假设或测试名称，优先使用 `CONTEXT.md` 中已经定义的术语，避免自行换同义词。

如果需要表达的概念还没有出现在 glossary 中，这通常意味着两种情况：

- 你正在引入项目里并不存在的语言，需要重新确认
- 当前文档确实缺少这个概念，应在后续通过相关文档技能补充

## ADR 冲突要显式指出

如果你的输出与已有 ADR 冲突，不要静默覆盖，应该明确指出，例如：

> 与 ADR-0007 冲突，但因为新的约束条件变化，值得重新评估。
